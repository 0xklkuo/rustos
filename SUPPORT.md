# Support

Thanks for your interest in `rustos`.

`rustos` is a small educational operating system project. Support is best-effort and mainly focused on helping contributors and learners understand the documented workflow, current scope, and active foundation work.

## Before asking for help

Please read these first:

1. `README.md`
2. `docs/spec.md`
3. `docs/architecture.md`
4. `docs/roadmap.md`
5. `CONTRIBUTING.md`

Most questions about scope, workflow, and current behavior are answered there.

## Where to ask

### GitHub Discussions

Use Discussions for:

- setup questions
- workflow questions
- architecture questions
- design feedback
- learning-oriented questions

### GitHub Issues

Use Issues for:

- reproducible bugs
- documentation mistakes
- focused improvement proposals

## What to include

For setup or workflow help, include:

- host operating system and architecture
- Rust toolchain version
- QEMU version
- the exact command you ran
- the full error output

For boot or emulator issues, include:

- the exact `xtask` command you ran
- the full boot log or failure output
- whether the issue happens consistently
- any firmware override environment variables you used

For design questions, include:

- the problem you are trying to solve
- why you think it fits `rustos`
- whether a smaller version would work

## Scope reminder

`rustos` is intentionally minimal.

Support is most useful for:

- understanding the current workflow
- clarifying the current project contract
- helping contributors make focused changes
- identifying real bugs or doc gaps

It is not intended to provide:

- guaranteed response times
- consulting for heavily modified forks without reproduction details
- support for features the project does not claim to have yet

## Security issues

Please do not report security-sensitive issues publicly.

Use the guidance in `SECURITY.md`.

## Contributing help

If you want to contribute but are unsure where to start:

1. read `CONTRIBUTING.md`
2. review `docs/roadmap.md`
3. look for small cleanup or documentation tasks first
4. ask a focused question before starting a large change
